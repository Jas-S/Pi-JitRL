# V1 scope

Version 0.1.0 is a standard Pi package with a separate learning core. It runs against the public extension API and leaves Pi's core code untouched. Git includes the compiled entry because Pi omits development dependencies when installing Git packages. CI rebuilds it and checks for drift.

The core handles state encoding, action classification, layered rewards, discounted returns, Jaccard retrieval and advantage estimation. SQLite persists trajectories across sessions. The adapter records tool events, injects numeric guidance and registers `/jitrl` commands. It restores the feedback target from the current session branch on reload or tree navigation.

V1 has three modes: `guide`, `observe` and `off`. The default is `guide`. Errors in observation pause the extension and report the problem; they do not block the user's tool calls. Reload after fixing the database or configuration issue.

## Verification boundary

Automated checks exercise core calculations, storage, lifecycle behavior, the Pi extension loader and actual bash exit statuses. A synthetic experiment demonstrates the reference-policy calculation. These checks establish that the package records and computes the expected values. They do not establish an improvement in coding-agent performance or prove that a hosted model follows the suggested probabilities.

The package targets the current Pi namespace, `@earendil-works/pi-coding-agent`. The manifest also lists the older `@mariozechner/pi-coding-agent` as an optional peer because the adapter uses hooks shared by both. The legacy namespace requires a separate compatibility check before claiming support for a specific release.

## Limits

Trajectories represent individual agent runs, rather than a task spanning arbitrary user follow-ups. A fresh run starts with empty recent-action history. Retrieval is local to the canonical working directory; it does not transfer experience between repositories by default.

Shell classification is conservative. Custom test commands and shell chains receive no verification reward unless they match the supported simple runners. Nested tool calls do not receive independent rewards. Successful command execution can still represent incomplete verification.

Active trajectories survive an unexpected process exit for inspection, but V1 does not resume them or retrieve from them. The retention limit applies to completed and aborted trajectories; stale active records require manual database maintenance. Large histories use a bounded recent-candidate scan rather than a vector index.

V1 does not include an embedding backend, automatic interpretation of user praise or criticism, forced tool selection, provider logit modification, or model training. The core/store boundary keeps those decisions separate from the Pi adapter.
